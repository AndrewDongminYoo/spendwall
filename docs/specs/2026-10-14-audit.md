# Append-only audit log (#11)

Implement an independent firewall audit boundary without modifying
`packages/policy` or claiming that the policy/approval execution paths are wired.
`AuditLog.append` accepts synthetic or future real tool/approval events. Decisions
are `allow`, `deny`, and `require_approval`; event kinds distinguish tool calls,
approval creation, approval decisions, and approval execution.

Postgres owns the event ID, UTC timestamp, chain serialization, and row hash.
An owner-only migration creates `audit.audit_events`, a singleton chain head,
and an append function. The unprivileged `spendwall_audit_app` group can read and
execute append but cannot insert directly, update, delete, truncate, or alter
objects. A row lock serializes append transactions, including across processes.
Rollback rolls back the head; sequence gaps are legitimate.

Each row contains every field requested in #11 plus `event_kind` and `row_hash`.
SHA-256 covers a versioned, explicit JSONB payload including ID, timestamp,
redacted data, metadata, and predecessor hash. Verification recomputes hashes
from actual columns in a repeatable-read snapshot and checks the independent
head, detecting the last-row mutation and removal as well as interior mutations.
Report the first failing row ID and ordinal, without printing row contents.
The schema owner is trusted: a full rewrite by the owner is outside the threat
model; an externally retained head hash is needed for stronger anchoring.

Hash the canonical original JSON arguments before discarding them. Persist only
allowlisted money/status/numeric context fields, recursively; discard unknown
keys and free text. IDs and names are bounded metadata labels, policy versions
are SHA-256 hashes, and approval/result references are UUIDs. Reject malformed
JSON, cycles, accessors, unsupported values and excessive size/depth before SQL.
Never persist upstream response bodies, credentials, headers, PII, or free text.
Database errors exposed by the module and CLI contain no connection or payload.

Use only a disposable local Postgres with synthetic data. No payment API,
credential creation, production migration, deployment, or merge is authorized.
The verifier only reads; migrations are a separate owner action. Run it with
`AUDIT_DATABASE_URL=... pnpm audit:verify` (URL is never printed).

Acceptance evidence: a real database records all three decisions and all four
event kinds, concurrent writers produce one valid chain, the app role's mutations
fail, rollback leaves no event/head change, changing any stored field reports its
exact row, and the CLI exits nonzero on tampering. Real policy/approval call-site
integration remains follow-up work with those owners.
