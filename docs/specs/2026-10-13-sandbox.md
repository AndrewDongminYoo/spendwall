# Sandbox readiness

## Problem and scope

Issue #2 needs US sandbox merchant and buyer accounts, a merchant REST app, and evidence that its client credentials can issue an access token.
Document account setup and provide a sandbox-only token check that reports safe metadata without exposing credentials or tokens.

## Constraints

Use Node's built-in HTTP support without new dependencies.
Keep the endpoint fixed to PayPal sandbox, reject redirects, and bound the request to 15 seconds.
Never log response bodies, credentials, authorization headers, or tokens.
Do not create orders, capture payments, or change Dashboard settings from this command.
Token issuance alone does not establish card-payment eligibility or MCP access.

## Acceptance

- The guide identifies account roles, US selection, REST app setup, feature checks, and token verification.
- Tests exercise request construction, credential validation, success metadata, invalid responses, and safe failure behavior.
- A real sandbox request succeeds before issue #2 is closed.
- Missing credentials leave live acceptance pending, even if local tests pass.

## Non-goals

MCP discovery, seed transactions, token caching, production authentication, and payment execution belong to later issues.
