## Observed blockers

- `docker-compose.yml` contains only local PostgreSQL; there is no application image or hosted service definition.
- Dashboard, approval and W0 MCP servers bind to loopback and compare Host/Origin against their local address.
- The W0 proxy remains separate from the synthetic policy/approval composition; publishing it would not establish an integrated payment-policy service.
- `migrations/001-audit.sql` and later migrations create database-specific roles and security-definer functions.
  Managed PostgreSQL compatibility needs verification under the provider's actual migration-owner permissions.
- AG Studio's [current licence guide](https://www.ag-grid.com/studio/react/enterprise-licence/) requires a licence for deployment and directs production evaluation to a trial licence.
  Public dashboard release stays blocked while trial issuance is deferred and no suitable existing licence is confirmed.
- Issue 20 requires a public dashboard and 48 hours of unattended upstream/token operation.
  Local containers and mocked refresh tests cannot satisfy those acceptance criteria.

## Recommended first delivery

Prepare one Render-targeted deployment-readiness PR without provisioning or publishing services.
Render is a proposed default because its documented web-service, managed PostgreSQL, HTTPS and same-region private-network model fits the existing Node/PostgreSQL application.
This is an engineering inference, not an established project precedent or provider compatibility result.
Oracle retrieval for hosting and public dashboard returned `[no precedent found]`; wiki freshness was unverified.

The first PR covers an explicitly configured hosted read-only dashboard entrypoint, a reproducible application image, a reviewable deployment template, database provisioning instructions and deployment checks.
The entrypoint serves only authenticated audit/statistics APIs and minimal readiness; the image builds the existing frontend but does not serve its assets while licence integration and release remain deferred.
No configuration flag enables the frontend in this entrypoint.
It must remain a partial delivery of issue 20, without closing the issue or claiming that webhook/mobile/payment composition is ready.
The existing local entrypoints retain their defaults.

### Network and authority

Hosted mode must require an explicit HTTPS public origin and deployment configuration; it must not infer authority from arbitrary forwarded headers.
Keep Host/Origin enforcement, dashboard authentication, request limits and safe error responses.
Bind the hosted process to the provider port on `0.0.0.0` only in explicit hosted mode.
Render documents this [port requirement](https://render.com/docs/web-services).

The judge-facing process receives a restricted audit reader, no schema-owner credentials, no PayPal credentials and no policy replay encryption or reviewer keys.
Policy proposal/replay/export and payment/approval mutation routes must remain unavailable in that process, regardless of client-supplied fields.
No anonymous audit data is proposed: use a separately distributed read-only access credential.
Live model queries remain disabled for the initial hosting preparation.
The health endpoint returns only minimal readiness and must not reveal database addresses, tokens or policy contents.

### Data and operations

Keep database traffic on private networking in the deployment template and require encrypted connections where supported by the provider contract.
Separate the migration owner from runtime credentials.
Use the existing migration files; do not relax append-only grants or silently rewrite applied migrations for hosting convenience.
Before any provisioned deployment, verify role creation, grants and security-definer behavior on the actual managed database.
If the provider cannot support the existing boundary, stop and revise the provider choice instead of elevating the application login.

Deployment must not run sandbox seed or submit payments automatically.
No automatic deployment from branch pushes is proposed before a separate release decision.
Keep token-manager code unchanged.
Plan a later authenticated backend composition and persistent refund ledger before claiming unattended payment operation.

### Cost and licence gate

Use paid always-on compute as the eventual operational baseline, not a free service that sleeps or a database with an evaluation expiry.
The [Render free-service documentation](https://render.com/docs/free) describes those limits.
The [current compute plan guide](https://render.com/docs/compute-plans) lists web plan `0.5c-512mb` and PostgreSQL plan `0.1c-256mb`; these are planning candidates, not approved purchases or proven capacity.
The [pricing page](https://render.com/pricing) and account-specific estimate must be checked before resource creation, including database storage and additional backend services.
No monthly amount is approved or guaranteed by this proposal.
Do not create resources until the operator confirms the target personal account, region, total budget and exact exposed services.
Do not serve the AG Studio bundle publicly until a valid deployment licence is confirmed; continue to defer issuance.

## Acceptance checks

1. Configuration and authority → real HTTP tests reject missing/incorrect hosted origin, spoofed forwarded headers and missing credentials; local defaults still pass existing tests.
2. Read-only deployment → direct requests cannot enable policy workshop, approval decisions or payment execution; runtime database credentials cannot mutate audit records.
3. Image → build from the pinned Node/pnpm versions with a frozen lockfile; run without local secrets, generated caches or a Docker daemon inside the container.
4. Lifecycle → health fails safely on unavailable data, shutdown closes listeners/pools, and restart does not seed or submit a payment.
5. Documentation → deployment template, provisioning order, licence/cost gate and remaining issue 20 criteria match the candidate.
6. Local delivery → `pnpm check`, image smoke tests, Trunk and Compose checks pass; security/network review and current-head hosted review/CI complete.
7. Full issue 20 completion, later → approved public deployment with valid licence plus an observed 48-hour unattended run of the integrated sandbox path.
   Mocked or short local checks do not replace this final criterion.
